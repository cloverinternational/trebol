# PageIndex agent-experience audit (2026-09-23)

## Baseline and live observations

PageIndex describes a document tree followed by LLM reasoning over that tree (`vendor/page-index/README.md`, lines 44–70). Its agent contract makes document browse the primary discovery step, offers paginated outlines and targeted content reads (`vendor/page-index/pageindex/agent_tools.py`, lines 65–75, 182–261), and returns actionable success/error envelopes (lines 311–324). This is a comparison of agent interfaces, not a claim that Pi-Swarm should copy its PDF/cloud features.

1. Before explicit indexing, `context_inspect` returned `[]` and `context_search("Where are request-scoped capabilities injected?")` returned `status: not-indexed`, `evidence: []`, and advice to index a source. Yet `memory_history.search(status=candidate, query="request-scoped capabilities")` returned both a concise candidate fact and the imported TaskManage Q&A with the answer and its file reference. The two stores are not joined. Code: `.pi/extensions/10-context/swarm-context.ts` lines 69–75, 156–185; `.pi/extensions/40-state/memory-history.ts` lines 182–204.
2. After `context_index(path="docs/reference/memory-integration-evidence.md")`, `context_search("What did the memory smoke prove, and what is not established about promotion?")` returned `status: ok`, two excerpts with sourceId/nodeId/line/hash, and a session-model fallback. `context_outline` listed hierarchical sections and summaries; `context_read(nodeIds=["0003"])` supplied the bounded cited section. This part is usable. Code: `.pi/lib/context/context-retrieval.ts` lines 74–109; `.pi/extensions/10-context/swarm-context.ts` lines 156–181.
3. The next `context_search("Where are TaskManage answers about CapabilityManifestState.apply and effective_capabilities?")` returned `no-result` with an honest note that its outline covers only the newly indexed document. The exact TaskManage Q&A was visible through `memory_history.search(status=candidate, query="Where are request-scoped capabilities formatted and injected?")`. This is a discoverability gap, not proof that the Q&A is correct.
4. Direct durable `recallKnowledge("CapabilityManifestState.apply")` returned `no-match` while direct candidate store `get(48b544e64653fb3827c566999a17400e)` contained the answer. A broad multi-hop question about prompt construction and capability injection returned several lexical partial matches but not that answer. Code: `.pi/lib/context/knowledge-recall.ts` lines 20–46 (candidate exclusion) and `.pi/lib/context/page-index-memory.ts` lines 33–40, 58 (Markdown-only nodes, token-substring ranking). Indexing the candidate's raw JSON as Markdown produced **zero nodes** and zero retrieved excerpts; its format cannot be projected unchanged into the tree.
5. `memory_history.search(status=candidate, query="nonexistent-zqv-index-probe")` returned empty arrays without an explicit `no-match`/`not-indexed` status or next step. The same query through `context_search` returned `no-result` after indexing, and `not-indexed` before indexing. The agent cannot infer whether the former search covered the desired scope or whether useful evidence exists in the other store. Code: `.pi/extensions/40-state/memory-history.ts` lines 188–204 versus `.pi/extensions/10-context/swarm-context.ts` lines 165–176.

## Prioritized agent-experience gaps

**P0 — One discoverable knowledge map.** The imported task answers are searchable as candidates but absent from `context_outline/search`, and verified-only bootstrap recall hides them. Inputs: current scoped KnowledgeStore records, candidate/verified status, task Q&A, original evidence, and revisions. Project each task as a Markdown tree (task → question → answer/evidence), not a JSON blob; present candidate state explicitly. Preserve the KnowledgeStore as authority and do not treat retrieval as verification. Output should link source ID, task/question IDs, revision, scope, status, and original evidence. On a missing/unreadable source, report the condition rather than silently omitting it. Acceptance query: ask about `CapabilityManifestState.apply`; the outline should expose the task/question and a read should show its attributed answer and evidence while marking it candidate.

**P1 — Progressive navigation over large imports.** The real candidate search returned an entire task JSON object for a single matching phrase, while `context_search` only sees manually indexed session sources. PageIndex's browse → paginated structure → targeted read avoids such dumps. Add scoped browse/search with page cursor and bounded source/question previews, then exact read by stable ID/revision. The current `memory_history` search uses substring on text/tags and slices to `limit` without pagination (`memory-history.ts` lines 188–204). Acceptance query: find one question among hundreds of task records without dumping full task bodies; read only that Q&A and its evidence.

**P1 — Honest relevance and absence.** The verified recall path scores lexical token overlap and returned plausible but irrelevant records for a multi-hop query; a candidate answer existed elsewhere. Use an outline-first reasoned selector over explicitly attributed candidate/verified cards, then inspect selected bodies and distinguish no-match, candidate-only, disabled, and failed retrieval. Keep exact-scope and evidence constraints. Acceptance query: the prompt-construction/capability-injection question should find both relevant questions or state that only unverified leads were found; nonsense should produce a clear negative result.

**P2 — Provenance and freshness at point of use.** Context `inspect` reports backing-file staleness, but `context_search` returns citations without the current/stale state. Task Q&A evidence references are not automatically checked when searched. Include source revision and freshness/availability in result and offer a reindex or source-read path. A stale/missing source must not be presented as current proof. Acceptance query: change an indexed backing file, then search; the result should flag stale and guide reindexing before reliance.

These are observed workflow gaps and proposed contracts; they are not claims of measured retrieval accuracy. No memories were verified or globally promoted during this audit.
