## Effectiveness and limits

**Verdict: partially effective, not yet reliable for unattended task recall.** Reloaded discovery works and preserves candidate labels/citations. The memory agent can select a correct Q&A for a narrow query and can return a verified record separately. Broad/multi-term queries sometimes fail without a receipt (`invalid-selection`), while generic words can fill its first twelve lexical cards with irrelevant task-process records before the agent has a chance to search wider. Its own uncertainty note does not prevent `status=ok` with unrelated or unanswered cards. The earlier isolated worker trace is not evidence that every live query succeeds.

The agent subprocess uses only `memory_browse`, `memory_read`, `memory_select`, up to eight tool calls and a 45-second timeout (`.pi/lib/context/memory-agent.ts#L9-L35`, `.pi/lib/state/memory-retrieval-worker.ts#L5-L34`). I did not directly inspect the transient child’s individual tool calls in this live session; its receipt is deleted after use. Thus I can confirm the parent tool output and unchanged target record, not a full internal browsing trace or a general no-write proof for all failures. I did not exercise an actual timeout, unavailable model, stale citation or cross-project scope isolation.

## Next fixes suggested by the observed failures

1. **Candidate selection before the agent:** remove generic question stopwords, score distinctive terms/phrases and task subject more heavily, and avoid selecting unanswered-only sections for factual questions. Do not let a broad query produce a misleading shortlist.
2. **Agent result contract:** return `no-result` when the agent says no card supports the query, regardless of incidental cards it selected. Preserve `candidate-leads` versus verified status at the top level.
3. **Recoverable agent failure:** persist a bounded, redacted read-tool/selection receipt for diagnosis. On `invalid-selection`, provide a safe outline and explanation or one bounded retry; never silently present a failed consultation as empty memory.
4. **Progressive browsing:** let the worker search and page the broader index, not merely browse the first twelve cards preselected by lexical matching. Keep exact provenance validation and read-only tool allowlist.
