# Memory integration evidence

## Proven in isolated stores

- Real-model, explicitly loaded extension: `memory_history` write, fresh-process
  read and revision-checked deletion. Found and fixed empty optional ID handling.
- Real-model lifecycle capture: a user-stated project storage decision and its
  offline rationale became a cited candidate with an incremental session cursor.
- Full package manifest (`settings.packages`, foreign workspace, isolated HOME),
  scripted provider: four processes exercised durable write, foreign-project
  isolation, fresh read/delete, and deletion persistence.
- Full package context tools: indexed source, resumed real Pi session, outline,
  cited body read, isolated retrieval consultation, delete, and another reload.
- Full package composite, five fresh sessions: lifecycle capture, candidate
  inspection, bootstrap exclusion of candidates, explicit fixture verification,
  then bootstrap retrieval with citation, revision and evidence references.

Local reproduction artifacts are under ignored `artifacts/memory-smoke/`:
`package-smoke.mjs`, `package-context.mjs`, `package-composite.mjs` and their
captured process outputs. They contain synthetic fixtures, not production facts.
The harness closes child stdin; leaving it open stalls print-mode input handling.

The package smoke exposed a Paseo delayed-startup callback using stale UI context
after shutdown. A generation guard and guarded notification fixed that crash;
focused tests cover stale and active-session outcomes.

## Not established

Scripted-provider integration is not retrieval-quality evidence. Explicit
fixture promotion is not automatic semantic verification. A citation to a user
statement supports attribution, not every possible interpretation of it.

Automatic verified promotion, live-TUI validation of global approval, reviewed history backfill,
and the full 20-conversation qualitative evaluation remain unfinished. Existing
experimental backfill facts are not approved for live ingestion. Context-index
session documents and durable knowledge records retain distinct lifetime
semantics; bootstrap reads the latter through a request-local PageIndex projection.

Known limits include per-scope recall scan caps, non-streaming child-output
buffering in Pi exec, and store path checks that do not defend against hostile
concurrent ancestor replacement. These limits must not be described as solved
by the successful fixture runs.

Global promotion now has a trusted interactive command and library tests for
decline, exact-revision approval, session replacement, and candidate refusal.
Those tests do not establish rendered TUI behavior or automatic fact verification.

## Bootstrap skill delivery follow-up

A live bootstrap call selected one skill, returned populated planner instructions,
and recalled all three reviewed repository decisions. Its full skill body still
caused more than 96k characters to be elided from the tool response: a count cap
alone did not bound delivery. Follow-up code caps each delivered skill at 12,000
characters, marks truncation, and supplies the registry SKILL.md path (or an
explicit paged SkillManage view fallback). Failed/empty skill results stop drafting.
The maximum remains two distinct skills. Thirteen focused bootstrap tests and the
bootstrap package build passed after this change; live verification of this latest
bounded-delivery change is still pending. Partial pilot-01 reading was extended,
without promoting records or claiming the 20-conversation evaluation complete.

### Exact spill and live continuation verified

Superseding the source-pointer-only delivery above: oversized invoked skill text
is now preserved in a unique private temporary file, with a 12,000 UTF-16-unit
inline preview (surrogate pairs preserved) and explicit `spillPath`. The marker
invites further file/shell reads, not another skill invocation; no tool-call
budget is introduced. Temporary spills may be removed by OS cleanup.

A live bootstrap selected one skill and returned a readable spill containing
170,808 bytes. Subsequent Bash calls read beyond the preview and then the file's
tail. This proves actual main-agent continuation, not merely file creation.
Seventeen focused tests passed, including threshold boundaries, exact UTF-8
readback, distinct spill paths, Unicode preview integrity, cap/order and failed
loads; bootstrap package build and diff check passed. The internal consultModel
leaf remains tool-disabled/one-shot; this change does not convert that leaf into
an iterative tool-using planner. The main orchestrator remains tool-capable.
