Use Git common-dir repository identity, isolated worktree and explicit global scope. Preserve legacy session entries. Empty index, no match, disabled and failed retrieval have different responses. Core project context stays small and contains discovery pointers, not all memories. Existing explicit scope/tool restrictions continue to apply.
5. Add enrichment lifecycle: capture bounded visible user statements, tool evidence and corrections, excluding reasoning and credentials; stage a cited candidate before promotion. At meaningful turn completion and before compaction, process only new evidence using persisted cursors and generation guards. Avoid recursive observer capture, repeated wakeups, blocking primary work and UI-dependent state. Failed/cancelled jobs remain retryable without duplicate writes. Repository facts require corroborating evidence or attributed explicit user decisions; unmerged facts stay worktree-scoped. Conflicts remain candidates rather than silent overwrites. No-write is valid.

Centralize agent-facing guidance for capture/retrieval/consolidation; test assembled prompts for contradiction, duplicate activation and misleading certainty. Keep global approval explicit and recorded.
7. Backfill in a previewable, resumable job from reviewed visible histories. Extract knowledge and decision rationale with conversation/message references; reconcile later corrections; check current source before labeling historical claims current. Deduplicate and classify procedural material for separate skill review. Apply reviewed project/worktree records only after isolated reload/retrieval proof. No automatic global duplication.
8. Validate real installed-extension round trips before quality evaluation: capture -> process restart/new session -> scoped outline/read -> bootstrap evidence -> correction/delete -> restart. Verify a foreign repository sees none of the private project facts. Then complete the 20-conversation pilot by reading calls/results/corrections, not scoring summaries alone. Keep remaining conversations untouched for validation; detect child sessions and related-session leakage. Use only evidence available before each replay task. Record per-case reasoning about knowledge usefulness, missed context and harmful/stale retrieval, with readable citations. Expand to 100 only after integration and pilot review pass; no blanket quality claim from unit tests or aggregate counts.

## Validation and stop conditions

Focused tests for scope, reload, citations/hash fidelity, correction/deletion, concurrent writes, redaction, malformed model output, cancellation, budgets, repeated hooks and disabled capabilities. Real runtime smoke in an isolated memory root; no production deployment or service mutation needed. Prompt/package builds and diff checks, then relevant integration suites. Do not claim end-to-end use from direct library tests. Stop promotion on cross-scope leaks, unsupported APIs, invented evidence or stale facts silently treated as current.

## Known limitations

The 20-conversation review is incomplete (pilot 01 partially read). Earlier experimental memory records mix facts and procedures and remain quarantined. No memory backend alone guarantees factual truth; provenance, explicit uncertainty and correction paths are required. Numerical benchmark summaries supplement, never replace, reading executions.
