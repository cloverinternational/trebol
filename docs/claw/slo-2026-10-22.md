# /claw self-supervision SLOs (2026-10-22)

The daemon now enforces written SLOs and acts on them, instead of the human prompting check-ups. Code:
`.pi/lib/claw/supervisor.ts` (decisions), `.pi/lib/claw/remedy.ts` (the one retry primitive), and the wiring in
`.pi/lib/claw/daemon.ts`. Tests: `.pi/test/claw/supervisor.test.ts` (fault injection, property) and
`.pi/test/claw/replay-2026-10-22.test.ts` (replay of the real store).

## 1. What today's runs actually did

2026-10-22T17:10Z) with `tools/claw/metrics.mjs`. The same window and the same numbers are reproduced from the
committed fixtures by `tools/claw/build-fixture-store.mjs`, so this is repeatable rather than a snapshot of a moving

| Symptom | Measured |

### The defect found today

`reconcileRun` closed a terminal run's tab only when the Tern snapshot had succeeded:

```ts
// .pi/lib/claw/daemon.ts @ origin/main before this change
if (CLOSE_ON_END.includes(run.status) && live !== undefined && run.block !== undefined && !run.tabClosedAt) {
	await closeRunTab(run, deps.tern).catch((e) => { run.tabCloseError = ... });
}
```

`tick` sets `live = undefined` exactly when `liveBlocks(tern)` throws, so an unresponsive Tern silently skipped the
close. Nothing retried it (`hasWork` did not count a pending close, so the daemon could exit inside the retry window),
nothing told the human (`tabCloseError` was never reported), and there was no inbox kind for a leftover tab.
Reproduced as a failing-then-passing test in `.pi/test/claw/supervisor.test.ts` ("closes a terminal run's tab even
when liveBlocks throws").

Independent corroboration from the live system, mid-afternoon: at 17:04:38Z a daemon running the deployed
`fix/claw-daemon-noise` code swept the store and closed 28 tabs in one pass — proving the close path works when the
snapshot succeeds — and left exactly the 6 `lost` runs open, because `lost` was excluded from `CLOSE_ON_END`. Both
halves of that sweep are now covered: the close no longer depends on the snapshot, and `lost` is included.

## 2. The SLOs and how each is enforced

Every bound is a constant in `DEFAULT_SLO` (`.pi/lib/claw/supervisor.ts:45`) and may be tightened per workspace in
`control.json` → `supervise` (validated: a negative or non-numeric value falls back to the default, never disables the
bound).

| # | SLO | Bound | Enforcement |
| --- | --- | --- | --- |
| S1a | A launching run becomes `running` or fails with a reason | 300 s (`launchMs`) | `daemon.ts:320` (launch timeout) |
| S1b | A worker tab that never reports `started` is named once | 90 s (`startedMs`) | `supervisor.ts:236` — reported, not relaunched (see §5) |
| S1c | An idle run is reported stalled, once per episode | 600 s (`idleNudgeMs`) | `supervisor.ts:137` → immediate `run_stalled` with the resuming command and the fail time |
| S1d | An idle run is ended by the supervisor with a real reason | 3600 s (`idleFailMs`) | `supervisor.ts:140` — `failed`, `failureClass: "stalled"`, Hoja untouched; `claw_send` resets the clock |
| S2a | A terminal run's tab is closed | 60 s of becoming terminal | `supervisor.ts:115` — attempted on the same tick, **not gated on the Tern snapshot** |
| S2b | A failed close is retried, then reported once | 5 attempts, 2 s→20 s jittered | `supervisor.ts:126` → `run_tab_orphan` naming `tern close <block>` |
| S2c | The daemon does not exit while it owes a retry or a digest | n/a | `daemon.ts:399` → `supervisionPending` |
| S3 | Each act happens at most once per run per state, inside a budget with jitter | per act | `remedy.ts` — `remedies["<action>:<state>"] = {attempts, nextAt, exhausted}`; deterministic jitter from the key so a replay is exact |
| S4a | Low-severity notices collapse into one digest | 300 s (`digestMs`) | `supervisor.ts:252` — `run_started`/`run_idle` go to `notices.jsonl`, one `claw_digest` per window |
| S4b | An all-clear heartbeat while workers are running | 1800 s (`heartbeatMs`) | `supervisor.ts:276` — at most one `claw_heartbeat` per window, and only while a run is launching/running; silence between heartbeats means healthy |
| S5 | A pending decision is visible and bounded, not idled on | 1800 s, 3 reminders | `supervisor.ts:176` — `awaitingSince` recorded, worker tab renamed to `! <id> decide`, reminder lines inside digests, budget then stops |
| S6a | A run that provably produced nothing is restarted | 1 attempt | `supervisor.ts` `recoveryReason` + `daemon.ts` `relaunchLaunch`: a launch failure with no tab, or a `lost` worker that never settled a turn; same run, same Hoja issue, only when no Tern block carries the run id |
| S6c | A run stuck past its deadline is never restarted, and says why | 1 record | `run_budget_spent`, one per run per act, naming the deadline and "no worker starts after expiry" |
| S6b | A Hoja lookup/create retry is paced, never re-sent | 5 attempts, 2 s→30 s jittered | `spawn.ts:175`, `spawn.ts:286` |

Non-goals, deliberately: the worker-local ask modal stays TREBOL-308's (this only flags the tab and reports the
question); launch-time transient-error retry and extension-health prechecks stay TREBOL-318's (this adds the
post-launch supervision of a run that got through).

## 3. Fault injection

`.pi/test/claw/supervisor.test.ts` (23 tests) injects real faults and asserts detection, a retry inside the budget,
and a truthful final state:

| Fault | Injected as | Asserted |
| --- | --- | --- |
| Tern snapshot fails | `inspect` throws (live = undefined) | tab still closed, no orphan item |
| Tern close keeps failing | `close` throws every time | exactly 5 attempts, one `run_tab_orphan`, `remedies["tab-close"].exhausted` |
| Daemon would exit mid-retry | failing close | `hasWork` true while retryable, false after the close succeeds |
| Worker killed mid-run | `alive() === false` | `lost`, one `run_lost`, tab closed on the next pass |
| Source file truncated while a launch reads it | a real half-file is imported | the import throws (`SyntaxError`); the run it produced ends `lost` with no finish, never completed |
| Tern unresponsive | `inspect` throws with a timeout | a live worker is not declared lost |
| Hoja 5xx | `resolve` throws 503 | 1 attempt on the first tick, 4 immediate ticks spend nothing, then paced to 5 → `failed ... gave up after 5 attempts; **no create**` |
| Worker stuck idle | `idleSince` 21 min ago, pid alive | one `run_stalled` report, then `failed` with `failureClass: "stalled"`, tab closed |
| Same fault on 20 consecutive ticks | failing close or an unrecoverable relaunch | no duplicate items (dedupe key + budget), one record |
| Worker killed before any settle | dead pid, no settle | `run_lost` once, tab closed, then `run_recovered` once and the same run relaunched on the same issue (no second Hoja create) |
| Stuck past its deadline | deadline in the past at the tab step | not restarted, failed with the reason, one `run_budget_spent` naming the deadline |
| Healthy run | live pid, live tab, one settle | untouched: no item, no notice, no ledger entry |

After-side simulation (stated because these cannot be replayed): worker liveness (`alive` answers true — no recorded
worker process exists any more), Tern (in-memory block set), Hoja (in-memory issue store, no network). Cancellation is
a human request, so the 15 recorded `run_cancelled` items have no replay counterpart; they are excluded from the
after-side actionable count by construction, not by suppression.

## 5. What this does not do, and what is still unknown

- A worker whose claw extension failed to load may still have executed the task. It is reported (no `started` event)
  and failed at the launch bound, but deliberately **not relaunched**: a second copy could duplicate side effects.
- The supervisor cannot shorten the human's response time to `needs_user`; it can only surface it immediately, flag
  the tab, repeat it in bounded digests, and stop.
- An idle worker may be sitting on a permission modal. The default posture is therefore `idleAction: "report"` (report
  and bound); `"send"` types one nudge into the tab and is opt-in, because a keystroke could approve a prompt for the
  human.
- A live worker whose tab was closed cannot be re-attached; the run records `tabMissingAt` and keeps collecting
  events. Only a launch that provably created no tab is retried.
- An unknown-outcome Hoja create (`create_dispatched`) is still never re-sent: absence of the marker is not proof that
  nothing was committed. It is retried by lookup with backoff and, at the bound, failed with the manual-check reason.
- Five of today's six `lost` runs wrote no event at all; with the startup diagnosis that landed in TREBOL-318 they replay
  as `failed` with the loader's stderr (`worker exited before session_start: ...`) instead of a silent `lost`. Both are
  truthful; the replay test asserts that duality rather than forcing one word.
- `PID` liveness is still `kill(pid, 0)` without start-time verification, so pid reuse remains theoretically possible.
- Wall-clock limits remain: a daemon that is killed inside a retry window leaves the work for the next start (the
  ledger is persisted, so the next daemon resumes rather than restarting the count).
